# 현장미러형 — 도면 치수 검증 시스템 아키텍처

> 설계 문서 (v1, 2026-07-24). 코드 이전 단계의 합의된 설계.
> 원칙: **"숫자가 기준"** — 모든 판단·비교의 축은 도면에서 읽은 수치(mm).

---

## 0. 목표 & 범위

- **최종 과제**: 도면의 치수 수치를 읽어 **실제 제품(3D 모델) 치수와 비교**해 일치/불일치 판정.
- **비교 대상 확정**: 3D 모델(합성)에서 렌더링한 도면 + 노이즈. 모델이 각 치수의 의미(어느 뷰·어느 피처)를 이미 알고 있음.
  → 핵심 난제였던 "값↔피처 연결"이 **"도면 추출 치수 ↔ 모델 생성 치수 매칭"** 으로 단순화됨(모델이 semantic 짊어짐).
- **처리량**: 소량 정밀 검수 → **Human-in-the-loop H1**(기계 제안 → 사람 확인/수정).
- **범위 밖**: 카메라 사진(구겨짐/조명), 임의 실무도면 완전자동 연결(= SOTA 오픈문제).
- **대상 도면**: clean CAD-export(선 뚜렷, ISO 규약 준수) + 합성.

## 1. 레이어 아키텍처 & 데이터 흐름

```
[도면 이미지]
   │
   ▼
① 텍스트 인식 (det + rec)           기계 ✅ 완성
   → [{raw_text, bbox, orientation}]
   │
   ▼
② 값 파싱                            기계 ✅ 규칙
   → {nominal, symbol, fit, tol_upper/lower, unit}
   │
   ▼
③ 뷰 분리                            기계 초안 + 사람 확인
   → views[]
   │
   ▼
④ 피처 검출 (구멍/외곽, CV)          기계 ✅ (선굵기 무관)
   → features[]
   │
   ▼
⑤ 앵커 검출 (화살촉 위치+방향)       기계 (학습 or CV) — 선 스타일분류 안 함
   → dimension.anchor
   │
   ▼
⑥ 연결 = 매칭                        기계 제안 + 사람 검증 (H1) ★핵심
   ├ (a) 도면내 값↔피처 후보연결(앵커/근접)
   └ (b) 도면치수 ↔ 3D모델치수 매칭
   → dimension.links, dimension.match
   │
   ▼
⑦ 비교/판정 & 리포트                 기계
   → within_tol? delta? mismatch 목록
```

**설계 핵심 결정 (근거)**:
- **선 스타일 분류(두께/점선) 안 씀** — 이질적 데이터에서 취약. 대신 **화살촉을 앵커로**(위치+방향). det의 "방향 못냄" 한계 때문에 PP-OCR과 **독립 모듈**로 둠.
- **피처 검출은 외곽선/구멍에서**(CV, 굵기 무관·견고). 지시선은 분할이 아니라 연결(⑥) 단서.
- **연결의 난이도를 사람에게 이관** — 기계는 "그럴듯한 후보 + 신뢰도"만, 정확성은 사람이 보증. 신뢰도 라우팅으로 사람은 애매한 것만.

## 2. 레이어별 명세

| 레이어 | 입력 | 출력 | 담당 | 방법 |
|---|---|---|---|---|
| ① 인식 | 이미지 | 텍스트 검출+인식 | 기계 | PP-OCRv6 det+rec (완성) |
| ② 파싱 | raw_text | 구조화 값 | 기계 | regex/규칙 (ø/±/fit/분수/각도) |
| ③ 뷰분리 | 이미지+검출 | views[] | 기계+사람 | 여백 클러스터링 + 뷰라벨텍스트, 사람 확인 |
| ④ 피처 | 이미지(뷰별) | features[] | 기계 | Hough circle(구멍) + contour(외곽) |
| ⑤ 앵커 | 이미지+치수bbox | 화살촉 위치/방향 | 기계 | keypoint 검출(학습, 합성지도) 또는 CV 삼각형+방향벡터 |
| ⑥ 연결·매칭 | ②④⑤ + 모델치수 | links, match | 기계+사람 | 후보생성(앵커/근접) → 신뢰도 라우팅 → 사람 검증 |
| ⑦ 비교 | match | 판정 리포트 | 기계 | 공차내 여부, delta, mismatch |

## 3. 핵심 데이터 스키마 (레이어 간 인터페이스)

모든 레이어가 이 단일 JSON을 읽고 채워나감. 인터페이스이자 최종 산출물이자 자기개선 데이터.

```json
{
  "drawing_id": "string",
  "image": { "w": 0, "h": 0 },

  "views": [
    { "view_id": "v1", "label": "front|side|section A-A|detail B|null",
      "bbox": [x0,y0,x1,y1], "confidence": 0.0, "source": "auto|human" }
  ],

  "features": [
    { "feature_id": "f1", "view_id": "v1",
      "type": "hole|contour|slot|other",
      "geometry": { "kind": "circle", "center": [x,y], "r": 0.0 },
      "confidence": 0.0, "source": "auto|human" }
  ],

  "dimensions": [
    { "dim_id": "d1", "view_id": "v1",
      "raw_text": "ø47g6", "bbox": [[x,y],...],
      "orientation": "h|v|<deg>",
      "parsed": { "nominal": 47.0, "symbol": "ø", "fit": "g6",
                  "tol_upper": null, "tol_lower": null, "unit": "mm" },
      "anchor": { "kind": "leader|dimline|none",
                  "arrowheads": [ { "pos": [x,y], "dir": [dx,dy] } ],
                  "span": [[x,y],[x,y]] },
      "links": [ { "feature_id": "f1", "role": "diameter|span_endpoint",
                   "confidence": 0.0, "source": "auto|human" } ],
      "match": { "model_dim_id": "m12", "status": "ok|mismatch|unmatched",
                 "delta": 0.0, "within_tol": true },
      "review": { "status": "auto_accepted|needs_review|human_confirmed|human_edited",
                  "confidence": 0.0 }
    }
  ],

  "provenance": {           // 자기개선 훅 (지금은 기록만, 재학습은 나중)
    "auto_link_count": 0, "human_edit_count": 0,
    "edits": [ { "dim_id": "d1", "field": "links", "before": {}, "after": {} } ]
  }
}
```

**설계 포인트**:
- `review.status` = H1 상태머신. 신뢰도 라우팅으로 `auto_accepted`(고신뢰) vs `needs_review`(애매) 결정.
- `match` = ⑦비교 결과. 3D모델 치수(`model_dim_id`)와 짝지어 delta·공차판정.
- `provenance.edits` = 사람 수정 로그 = **미래 재학습용 정답 데이터**(구조만 예약, 지금 재학습 안 함).

## 4. ⑥ 연결 = 매칭 재정의 (3D 모델 활용)

비교대상이 3D 모델(합성)이라 **모델이 정답을 앎** → 연결이 매칭으로 붕괴:

```
모델 측 (합성 3D → 도면 렌더):
  emits model_dims[] = [{model_dim_id, value, view, feature, span}]  ← 정답 포함

도면 측 (렌더+노이즈 이미지에 우리 파이프라인):
  extracts dimensions[] = [{값, 위치, 뷰영역, 방향}]  ← OCR 결과

⑥ 매칭: dimensions[i] ↔ model_dims[j]
  키 = {값 근사일치, 뷰영역 일치, 방향 일치}  ← 퍼지 매칭 (피처 재구성 불필요)
  애매/충돌 → 사람(H1)

⑦ 비교: 매칭된 쌍의 도면값 vs 모델값
  일치 = OCR·연결 정상 / 불일치 = OCR오류 or 도면-모델 불일치
```

- **합성**: 양측 정답 다 있음 → 매칭 정확도 **자동 정량평가 가능**(우리 프로젝트 고유 강점).
- **실도면(모델 없음)**: 같은 매칭 UI 쓰되 사람 입력 비중↑, 또는 도면내 값↔피처 연결(⑥a)까지만.

## 5. Human-in-the-loop (H1) 상호작용 명세

**화면**: 도면 + 기계 후보연결선(신뢰도 색상).
**사람 액션 3종**:
- 🟢 고신뢰(auto_accepted) → 통과 (사람 안 봄)
- 🟡 애매(needs_review) → 맞으면 클릭 확정, 틀리면 올바른 피처로 드래그
- 🔴 누락/오류 → 연결 추가·삭제

**사람 노동 최소화 장치**:
1. **신뢰도 라우팅** — 고신뢰 자동확정, 애매한 것만 큐잉. 사람은 하위 N%만.
2. **선묶기** — 멀티라인 콜아웃(`ø25 REAMED`+`THRU HOLE`+`1 NO.`), 적층공차를 미리 한 덩어리로.
3. **스마트 기본값** — "가장 가까운 피처" 기본연결 → accept/reject.

**노동량** ≈ 치수개수 × (1 − 자동확정율). 자동확정율은 신뢰도 임계로 조절.

## 6. 자기개선 루프 (구조 예약)

- 사람 수정(`provenance.edits`)을 정답으로 축적.
- 지금: **기록만**. 재학습 파이프라인 안 만듦.
- 나중: 축적된 정답으로 ⑤앵커/⑥연결기(관계예측) 재학습 → 자동확정율↑ → 사람노동↓.
- 스키마에 훅만 박아둬서 나중에 무손실 확장 가능.

## 7. 합성 / 실도면 이원 전략

| | 합성(3D모델) | 실도면(CAD-export) |
|---|---|---|
| 정답 | 있음(모델) | 없음 |
| 용도 | 파이프라인 정량평가·튜닝, (미래)연결기 학습 | 실사용·사람검수 |
| ⑥ | 값↔모델 매칭 자동평가 | 값↔피처 연결(사람 검증) |

- 합성으로 **개발·검증**, 실도면으로 **적용**. det/rec은 이미 실도면 라벨로 학습됨.

## 8. 구현 순서 (마일스톤)

1. **스키마 확정 + 파서(②)** — raw_text → parsed. 규칙, 즉시 가능.
2. **뷰 분리(③)** — 여백클러스터+뷰라벨, 합성 정답으로 평가.
3. **피처 검출(④)** — Hough circle + contour, 뷰별.
4. **앵커 검출(⑤)** — 먼저 CV(삼각형+방향) 프로토타입 → 부족하면 학습(합성지도).
5. **연결 후보생성 + 신뢰도(⑥a)** — 앵커방향/근접 규칙.
6. **매칭(⑥b) + 비교(⑦)** — 합성 모델치수와 매칭, 정량평가.
7. **H1 검수 UI** — 후보연결 오버레이 + 3액션.
8. (나중) 자기개선 재학습.

각 단계는 **합성에서 정량평가 → 실도면 적용** 순.

## 9. 선행연구 근거 / baseline 맵핑

| 우리 레이어 | 근거/baseline 논문 | 관계 |
|---|---|---|
| ① 인식 | MDPI Machines 2023, YOLO+Donut(arXiv 2505.01530) | 인식·추출은 SOTA급으로 다져짐, 우리도 도달 |
| ⑤ 앵커/선 | GCN 컴포넌트 세그멘테이션(arXiv 2212.00290) | 선 타입분류 접근, 우린 화살촉앵커로 대체 |
| ⑥ 연결 | Su 2002(dimension-driven CAD, 규칙+coordinate grid) | **유일한 직접 선례**, 우리 baseline |
| ⑥ 연결(학습화 시) | Associative reasoning(Autom.Constr. 2025) | attention+knowledge graph, 단 목적은 도면검색 |

**니치**: raster에서 "치수값↔물리 피처 연결"을 정면으로 푼 현대 딥러닝 연구는 사실상 없음. 우리는 (1)clean 한정 (2)3D모델 매칭으로 단순화 (3)H1 반자동 — 오픈문제를 우회해 실현.

## 10. 리스크 & 정직한 한계

- **⑤앵커 CV가 이질적 데이터에서 흔들릴 수 있음** → 학습(합성지도)로 승격 대비.
- **⑥ 완전자동 연결은 오픈문제** → H1으로 정확성 보증, "완전자동"을 KPI로 걸지 않음.
- **뷰분리 애매 케이스**(뷰 경계 붙은 도면) → 사람 확인으로 보완.
- **실도면엔 모델정답 없음** → 매칭의 자동평가는 합성에서만. 실도면은 사람검증 정확도로 평가.
- **방어 프레이밍**: "clean CAD 한정 + 3D모델 매칭 + H1 반자동 + 자기개선 훅" = 정직하고 실현가능하며 기여도 있음. 완전자동 일반화는 명시적 향후과제.
